## 1. Foundation Model과 Post-Training

### 1.1 Foundation Model이란?

Foundation Model(기반 모델)은 **대규모 데이터로 사전 학습되어 다양한 하위 작업에 적용할 수 있는 대형 모델**입니다. Cosmos Transfer 2.5는 NVIDIA가 만든 **World Foundation Model (WFM)** 로, 물리 세계의 시각적 시뮬레이션을 생성하기 위해 설계되었습니다.

```
Foundation Model의 학습 흐름:

[대규모 데이터] → [Pre-training] → [Foundation Model] → [Post-training] → [도메인 특화 모델]
  (수백만 비디오)    (범용 학습)      (Cosmos Transfer 2.5)   (추가 학습)      (나만의 모델)
```

### 1.2 Post-Training의 위치와 역할

| 단계 | 목적 | 데이터 규모 | 학습 시간 |
|------|------|------------|----------|
| **Pre-training** | 범용적 세계 이해 학습 | 수백만~수천만 | 수주~수개월 |
| **Post-training** | 특정 도메인 적응 | 수백~수천 | 수시간~수일 |
| **Inference** | 학습된 모델로 생성 | - | 수초~수분 |

Post-training이 중요한 이유:
- Pre-training에서 학습한 **범용적 지식을 보존**하면서
- **특정 도메인의 시각적 패턴**을 추가로 학습
- 전체 모델을 처음부터 학습하는 것보다 **훨씬 효율적**

### 1.3 Post-Training 전략들

NVIDIA Cosmos에서 제공하는 3가지 post-training 전략:

#### (1) Full Post-Training (전체 파라미터 업데이트)
- **모든 모델 파라미터**를 업데이트
- 충분한 학습 데이터가 있을 때 적합
- 가장 높은 성능, 가장 많은 GPU 메모리 필요
- **Cosmos Transfer 2.5의 기본 방식**

#### (2) LoRA Post-Training (저랭크 적응)
- **일부 저랭크 파라미터만** 업데이트
- 적은 데이터와 컴퓨팅 자원으로 가능
- 기본 모델의 능력을 잘 보존
- Cosmos Predict 계열에서 지원

#### (3) Reinforcement Learning (강화 학습)
- 고품질 데이터가 부족할 때 사용
- Cosmos Reason 모델에서 지원
- Diffusion 모델(Predict/Transfer)에는 현재 미지원

### 1.4 Post-Training의 핵심 변수들

```
Post-Training 성공 = f(데이터 품질, 학습 전략, 하이퍼파라미터)
```

| 변수 | 설명 | 조언 |
|------|------|------|
| **데이터 혼합** | 학습 데이터의 구성 비율 | 2단계 접근: 넓은 노출 → 고품질 집중 |
| **학습 전략** | Full vs LoRA vs RL | 데이터 규모와 목표에 따라 선택 |
| **하이퍼파라미터** | LR, 배치 크기, 옵티마이저 | 소규모 실험으로 최적값 탐색 |
| **데이터 증강/필터링** | 노이즈 제거, 합성 데이터 | 신호 밀도 향상과 현실성 개선 |

## 2. Diffusion Model 기초

### 2.1 Diffusion Model이란?

Diffusion Model은 **데이터에 점진적으로 노이즈를 추가한 후, 그 노이즈를 제거하는 방법을 학습**하여 새로운 데이터를 생성하는 생성 모델입니다.

```
Forward Process (노이즈 추가):
원본 이미지 x₀ → x₁ → x₂ → ... → xₜ (순수 노이즈)

Reverse Process (노이즈 제거 - 모델이 학습하는 것):
순수 노이즈 xₜ → xₜ₋₁ → ... → x₁ → x₀ (생성된 이미지)
```

### 2.2 수학적 직관

**Forward Process** (고정, 학습하지 않음):
```
q(xₜ | xₜ₋₁) = N(xₜ; √(1-βₜ)·xₜ₋₁, βₜ·I)

여기서:
- βₜ: 시간 t에서의 노이즈 스케줄 (작은 양의 노이즈)
- N: 가우시안 분포
- 각 스텝에서 조금씩 가우시안 노이즈를 추가
```

**Reverse Process** (모델이 학습):
```
pθ(xₜ₋₁ | xₜ) = N(xₜ₋₁; μθ(xₜ, t), Σθ(xₜ, t))

여기서:
- μθ: 모델이 예측하는 노이즈 제거된 평균
- θ: 학습 가능한 파라미터 (신경망의 가중치)
- 모델은 현재 노이즈가 있는 상태에서 이전 상태를 예측
```

### 2.3 학습 목표 (Training Objective)

Diffusion Model의 학습은 **노이즈 예측**으로 단순화됩니다:

```
Loss = E[‖ε - εθ(xₜ, t)‖²]

여기서:
- ε: 실제로 추가된 노이즈 (정답)
- εθ(xₜ, t): 모델이 예측한 노이즈
- xₜ: 시간 t에서의 노이즈가 추가된 이미지
- 모델은 "이 이미지에서 노이즈 부분이 뭔지" 맞추는 것을 학습
```

이 손실함수가 최소화되면, 모델은 **노이즈를 정확하게 예측**할 수 있고, 이를 원래 이미지에서 빼면 **깨끗한 이미지를 생성**할 수 있습니다.

### 2.4 Latent Diffusion (잠재 공간 확산)

직접 픽셀 공간에서 작업하면 연산 비용이 매우 높으므로, Cosmos Transfer 2.5는 **잠재 공간(latent space)**에서 diffusion을 수행합니다:

```
원본 비디오 → [인코더] → 잠재 표현 z₀ → Diffusion → [디코더] → 생성된 비디오
  (높은 차원)              (낮은 차원)                        (높은 차원)

비디오 프레임 크기:    704 × 1280 × 93 프레임
잠재 표현 크기:        ~88 × 160 × 24 (state_t)
압축 비율:             약 8× 공간, 약 4× 시간
```

**핵심 관계식:**
```
num_frames = (state_t - 1) × 4 + 1
예: state_t = 24 → num_frames = (24-1) × 4 + 1 = 93

이것은 시간 축 압축 비율이 ~4배라는 의미:
- 93개 비디오 프레임이 24개 잠재 프레임으로 압축
- 각 잠재 프레임은 ~4개의 비디오 프레임 정보를 담고 있음
```

## 3. Diffusion Transformer (DiT)

### 3.1 기존 U-Net vs DiT

초기 Diffusion Model은 **U-Net** 아키텍처를 사용했지만, 최신 모델들은 **Transformer 기반 아키텍처(DiT)**로 전환하고 있습니다.

| 특성 | U-Net | DiT (Diffusion Transformer) |
|------|-------|----------------------------|
| 구조 | 인코더-디코더 + Skip Connection | Transformer 블록 스택 |
| 확장성 | 제한적 | 뛰어남 (파라미터 수에 비례) |
| 어텐션 | 일부 레이어에만 | 모든 레이어에 |
| 조건 입력 | AdaGN, Cross-Attention | AdaLN, Cross-Attention |

### 3.2 DiT 블록 구조

Cosmos Transfer 2.5의 DiT는 다음 블록들이 반복되는 구조입니다:

```
입력 잠재 표현
    │
    ▼
┌──────────────────────┐
│  Adaptive LayerNorm  │  ← 시간 정보(t) 임베딩
│  (AdaLN-Zero)        │
├──────────────────────┤
│  Self-Attention      │  ← 공간-시간 관계 학습
├──────────────────────┤
│  Cross-Attention     │  ← 텍스트 조건 주입
├──────────────────────┤
│  Feed-Forward (FFN)  │  ← 비선형 변환
└──────────────────────┘
    │
    ▼
다음 블록으로
```

**각 구성 요소의 역할:**

| 구성 요소 | 역할 | 설명 |
|-----------|------|------|
| **AdaLN** | 시간 정보 주입 | Denoising 시간 t를 모델에 알려줌 |
| **Self-Attention** | 공간-시간 관계 | 프레임 내/프레임 간 관계 학습 |
| **Cross-Attention** | 텍스트 조건 | 텍스트 프롬프트에 따른 생성 제어 |
| **FFN** | 특성 변환 | 비선형 변환으로 표현력 확장 |

### 3.3 Adaptive Layer Normalization (AdaLN)

일반적인 Layer Normalization과 달리, AdaLN은 **시간 정보에 따라 정규화 파라미터가 동적으로 변합니다**:

```
일반 LayerNorm:  y = γ · norm(x) + β        (γ, β는 고정 학습 파라미터)
AdaLN:           y = γ(t) · norm(x) + β(t)   (γ, β가 시간 t에 따라 변화)

이것이 중요한 이유:
- 노이즈가 많은 초기 단계(t가 클 때)에서는 다른 정규화 적용
- 거의 깨끗한 후기 단계(t가 작을 때)에서는 또 다른 정규화 적용
- 각 denoising 단계에 맞는 최적의 처리 가능
```

## 4. ControlNet 아키텍처

### 4.1 ControlNet이란?

ControlNet은 **사전 학습된 diffusion 모델에 공간적 제어를 추가**하기 위한 아키텍처입니다. 기본 모델의 가중치를 보존하면서 추가적인 제어 신호를 주입합니다.

### 4.2 Cosmos Transfer 2.5의 ControlNet 설계

```
                    ┌─────────────────────────┐
제어 입력            │   Control Branch         │
(edge/depth/        │   (3개의 Transformer     │
 seg/vis)     ────→ │    블록 복제)             │
                    │                         │
                    │  블록 1 → Linear(0) ──────────→ + 기본 모델 블록 1
                    │  블록 2 → Linear(0) ──────────→ + 기본 모델 블록 2
                    │  블록 3 → Linear(0) ──────────→ + 기본 모델 블록 3
                    └─────────────────────────┘
                                                      │
텍스트 프롬프트 ────────────────────────────────→ 기본 모델 (DiT)
                                                      │
노이즈 + 잠재 입력 ────────────────────────────→      │
                                                      ▼
                                                  생성 결과
```

**핵심 설계 원칙:**

1. **블록 복제**: 기본 모델의 Transformer 블록 일부(3개)를 복제하여 제어 브랜치 생성
2. **가중치 상속**: 복제된 블록은 기본 모델의 가중치로 초기화
3. **Zero-Initialization**: Linear 레이어는 0으로 초기화 → 학습 초기에는 제어 신호가 기본 모델에 영향을 주지 않음
4. **잔차 연결**: 제어 브랜치의 출력이 기본 모델의 대응 블록 활성화에 더해짐

**왜 3개 블록인가?**
> *"Three conditional blocks empirically offer a good balance between control effectiveness and inference efficiency."*
> — NVIDIA의 실험적 발견으로, 3개 블록이 제어 효과와 추론 효율성 사이의 최적 균형점

### 4.3 멀티 모달 제어

여러 제어 입력을 동시에 사용할 때:

```
Edge 입력    → Control Branch 1 → 제어 신호 1 ─┐
Depth 입력   → Control Branch 2 → 제어 신호 2 ─┤→ 시공간 가중 맵 → 결합 → 기본 모델
Seg 입력     → Control Branch 3 → 제어 신호 3 ─┤   으로 결합
Vis 입력     → Control Branch 4 → 제어 신호 4 ─┘
```

**시공간 제어 맵 (Spatiotemporal Control Map):**
- 각 모달리티에 대해 **위치와 시간에 따른 가중치**를 지정
- 가중치가 높을수록 해당 모달리티의 영향력이 큼
- 가중치 합이 1.0 이하이면 그대로 적용, 1.0 초과 시 비례적으로 정규화

### 4.4 Zero-Initialization의 중요성

```
학습 초기:
  Linear 출력 = W·x + b = 0·x + 0 = 0
  → 제어 신호가 기본 모델에 전혀 영향 없음
  → 기본 모델의 사전 학습된 능력이 완전히 보존됨

학습 진행:
  Linear 가중치가 점진적으로 업데이트
  → 제어 신호가 서서히 기본 모델에 주입됨
  → 안정적인 학습 과정 보장
```

이 설계 덕분에:
- 학습 초기에 **기본 모델의 붕괴 방지**
- **점진적으로 제어 능력 획득**
- 학습 안정성이 크게 향상

## 5. Cosmos Transfer 2.5의 전체 아키텍처

### 5.1 모델 구성 요소

```
┌─────────────────────────────────────────────────────────────┐
│                    Cosmos Transfer 2.5                       │
│                                                             │
│  ┌─────────────┐    ┌──────────────────────────────────┐   │
│  │ 텍스트 인코더  │    │     기본 모델 (DiT, 2B params)    │   │
│  │ Qwen2.5-VL   │──→│                                  │   │
│  │ -7B          │    │  Self-Attn → Cross-Attn → FFN   │   │
│  │ (28 레이어)   │    │         × N 블록 반복             │   │
│  └─────────────┘    │                                  │   │
│                      │          ↑ 제어 신호 주입          │   │
│  ┌─────────────┐    │     ┌──────────────────┐        │   │
│  │ 비디오 토크  │    │     │ ControlNet 브랜치  │        │   │
│  │ 나이저      │    │     │ (3 블록 × modality) │        │   │
│  │ (인코더/    │    │     └──────────────────┘        │   │
│  │  디코더)    │    │                                  │   │
│  └─────────────┘    └──────────────────────────────────┘   │
│                                                             │
│  모델 크기: 2B 파라미터 (Transfer1의 7B에서 3.5× 축소)        │
└─────────────────────────────────────────────────────────────┘
```

### 5.2 텍스트 인코더: Qwen2.5-VL-7B

Cosmos Transfer 2.5는 텍스트 인코딩에 **Qwen2.5-VL-7B** (코드명: `reason1p1_7B`)을 사용합니다.

```python
text_encoder_class = "reason1p1_7B"          # Qwen2.5-VL-7B
embedding_concat_strategy = "FULL_CONCAT"    # 28개 레이어 전체 연결
crossattn_proj_in_channels = 100352          # = 3584 × 28
crossattn_emb_channels = 1024               # 투영 후 차원
```

**FULL_CONCAT 전략의 의미:**
```
Qwen2.5-VL-7B의 28개 레이어 각각에서 텍스트 임베딩 추출:
  레이어 1 출력: [seq_len, 3584]
  레이어 2 출력: [seq_len, 3584]
  ...
  레이어 28 출력: [seq_len, 3584]

모든 레이어 연결: [seq_len, 3584 × 28 = 100,352]
투영 레이어:     [seq_len, 100,352] → [seq_len, 1024]
Cross-Attention: DiT가 이 1024차원 텍스트 표현에 attend
```

이 방식은 텍스트 인코더의 **모든 레이어 정보를 활용**하여 더 풍부한 텍스트 조건을 제공합니다. 얕은 레이어는 문법/구문 정보를, 깊은 레이어는 의미/맥락 정보를 담고 있으므로 이를 모두 사용합니다.

### 5.3 비디오 토크나이저

비디오를 잠재 공간으로 압축하는 인코더-디코더:

```
입력 비디오: [B, C, T, H, W] = [배치, 3, 93, 704, 1280]
                    │
                    ▼ (인코더)
잠재 표현:   [B, C', T', H', W'] = [배치, C', 24, ~88, ~160]
                    │
                    ▼ (DiT에서 denoising)
                    │
                    ▼ (디코더)
출력 비디오: [B, C, T, H, W] = [배치, 3, 93, 704, 1280]

시간 축 압축: 93 → 24 (약 4배)
공간 축 압축: 704×1280 → ~88×160 (약 8배)
```

### 5.4 Augment Noise (증강 노이즈)

조건부 생성(이미지/비디오 입력 기반)에서 중요한 기법:

```
학습 시:
  조건 잠재 프레임에 소량의 노이즈 추가 (augment noise)
  → 모델이 약간의 노이즈에도 강건하게 학습

추론 시:
  조건 잠재 프레임에는 노이즈를 추가하지 않음
  → 깨끗한 조건 입력 사용

목적: 학습과 추론 사이의 간극(gap) 줄이기
```

**원리**: Canny 엣지 감지 알고리즘으로 비디오의 윤곽선을 추출하여 구조적 가이드로 사용

**적합한 용도:**
- 로봇/자율주행 등 3D 공간 인식이 중요한 경우
- 카메라 움직임의 일관성 유지
- 새 객체를 현실적인 위치에 배치

### 6.3 Segmentation (세그멘테이션) 제어

**원리**: SAM2 모델로 비디오에서 객체별 마스크를 추출하여 의미론적 가이드로 사용

```
원본 프레임:        세그멘테이션 맵:       생성 결과:
┌──────────┐      ┌──────────┐         ┌──────────┐
│ 사람 🧑   │      │ ■■■ (빨강)│         │ 로봇 🤖  │
│ 자동차 🚗 │  →   │ ▓▓▓ (파랑)│     →   │ 트럭 🚛  │
│ 도로 ━━━ │      │ ░░░ (녹색)│         │ 도로 ━━━ │
└──────────┘      └──────────┘         └──────────┘

보존되는 것: 객체의 영역, 의미론적 구조
변경 가능한 것: 객체의 모양, 종류, 텍스처
```

**주의사항:**
- 반드시 마스크와 함께 사용 (단독 사용 시 할루시네이션 발생 가능)
- 멀티 컨트롤 설정에서 사용 권장 (Edge + Seg 등)
- 가중치가 너무 높으면 비현실적인 객체 생성 위험

### 6.4 Visual Blur (Vis) 제어

**원리**: 원본 비디오를 블러 처리하여 전체적인 분위기/조명/배경을 가이드로 사용

```
원본 프레임:        블러 처리:            생성 결과:
┌──────────┐      ┌──────────┐         ┌──────────┐
│ 선명한    │      │ 흐릿한    │         │ 원래와    │
│ 장면     │  →   │ 윤곽만    │     →   │ 비슷한    │
│          │      │ 보이는    │         │ 분위기    │
└──────────┘      └──────────┘         └──────────┘

보존되는 것: 배경 분위기, 조명, 전체적 외관
변경 가능한 것: 세부 디테일, 객체
```

**사용 팁:**
- Edge나 Seg와 함께 보조적으로 사용 (낮은 가중치: 0.4-0.6)
- 단독으로 마스크 적용하면 할루시네이션 발생
- 가중치가 너무 높으면 원본 비디오 그대로 출력

### 6.5 멀티 컨트롤 조합 전략

여러 제어 입력을 조합하면 더 정교한 결과를 얻을 수 있습니다:

```
예시: 배경 교체 워크플로우

1단계: Edge만 사용
   → 피사체 움직임은 보존되지만 배경이 비현실적

2단계: Edge + Vis 추가
   → 조명 일관성 추가, 시각적 왜곡 감소

3단계: Edge + Vis + Seg(마스크 적용)
   → 배경 영역에 의미 정보 주입 → 선명하고 현실적인 결과
```

**가중치 정규화 규칙:**
- 총 가중치 합 ≤ 1.0 → 그대로 적용
- 총 가중치 합 > 1.0 → 비례적으로 정규화하여 합이 1.0이 되도록

## 7. 학습 과정의 핵심 개념

### 7.1 Learning Rate Warmup

```
학습률 (LR)
    │
5e-5├────────────────────────────────
    │      ╱
    │    ╱
    │  ╱
0   ├╱─────┬──────────────────────→ iteration
    0   1000                   5000
        └ warmup 구간
```

**왜 Warmup이 필요한가?**
- 학습 초기에 그래디언트가 매우 클 수 있음
- 높은 학습률로 바로 시작하면 **그래디언트 폭발** 위험
- 낮은 학습률에서 시작하여 점진적으로 올리면 **안정적 학습 시작**
- Cosmos Transfer 2.5의 기본 warmup: **1000 스텝**

### 7.2 Gradient Accumulation

```python
grad_accum_iter = 4  # 4번의 forward/backward를 모아서 1번 업데이트

# 의미:
# 실제 배치 크기 = 물리적 배치 크기 × grad_accum_iter
# 예: 물리적 배치 1 × grad_accum 4 = 유효 배치 4
#
# 장점:
# - GPU 메모리를 아끼면서 큰 배치 효과를 낼 수 있음
# - 그래디언트가 더 안정적 (여러 샘플의 평균)
```

### 7.3 Exponential Moving Average (EMA)

학습 중 모델 가중치의 **지수 이동 평균**을 유지합니다:

```
EMA 가중치 = α × 현재 가중치 + (1 - α) × 이전 EMA 가중치

여기서 α는 매우 작은 값 (예: 0.001)

직관:
- 학습 중 가중치는 노이즈처럼 진동함
- EMA는 이 진동을 부드럽게 평균냄
- 결과적으로 더 안정적이고 일반화된 모델 제공
```

**체크포인트 파일에서:**
- `model.pt`: 마지막 iteration의 가중치 (진동 포함)
- `model_ema_bf16.pt`: EMA 평균 가중치 (더 안정적) ← **추론에 사용 권장**
- `model_ema_fp32.pt`: EMA 가중치 FP32 정밀도

### 7.4 FSDP (Fully Sharded Data Parallel)

Cosmos Transfer 2.5는 **FSDP**를 사용하여 대형 모델을 여러 GPU에 분산합니다:

```
전통적 Data Parallel:
  GPU 0: [전체 모델 복사본] + 데이터 배치 1
  GPU 1: [전체 모델 복사본] + 데이터 배치 2
  → 각 GPU에 전체 모델이 복제되어 메모리 낭비

FSDP (Fully Sharded):
  GPU 0: [모델 조각 1/8] + 데이터 배치 1
  GPU 1: [모델 조각 2/8] + 데이터 배치 2
  ...
  GPU 7: [모델 조각 8/8] + 데이터 배치 8
  → 필요할 때만 다른 GPU의 조각을 통신으로 가져옴
  → GPU당 메모리 사용량 대폭 감소
```

### 7.5 Context Parallelism

Cosmos Transfer 2.5의 독특한 병렬화 기법으로, **시간 축(시퀀스)을 여러 GPU에 분할**합니다:

```python
context_parallel_size = 8  # state_t의 약수여야 함

# state_t = 24, context_parallel_size = 8인 경우:
# GPU당 잠재 프레임 수 = 24 ÷ 8 = 3

# GPU 0: 잠재 프레임 [0, 1, 2]
# GPU 1: 잠재 프레임 [3, 4, 5]
# GPU 2: 잠재 프레임 [6, 7, 8]
# ...
# GPU 7: 잠재 프레임 [21, 22, 23]
```

**context_parallel_size의 선택:**
| context_parallel_size | GPU당 프레임 | 메모리 사용 | 통신 오버헤드 |
|----------------------|------------|-----------|-------------|
| 4 | 6 | 높음 | 낮음 |
| 8 (기본) | 3 | 중간 | 중간 |
| 12 | 2 | 낮음 | 높음 |
| 24 | 1 | 최소 | 최대 |

## 8. 데이터 큐레이션의 과학

### 8.1 NVIDIA의 7단계 데이터 큐레이션 파이프라인

Cosmos의 사전 학습에 사용된 데이터 큐레이션 파이프라인을 이해하면 post-training 데이터 준비에도 도움이 됩니다:

```
원본 비디오 수집
    │
    ▼
1. Shot-Aware Video Splitting (장면 경계 감지 분할, 5-60초 클립)
    │
    ▼
2. GPU-Based Transcoding (형식/프레임레이트/압축 최적화)
    │
    ▼
3. Video Cropping (테두리/레터박스 제거, 일관된 종횡비)
    │
    ▼
4. Multi-Stage Filtering (품질 필터링)
    │  - 미학적 품질 분류기
    │  - 모션 분석
    │  - OCR (자막/텍스트 감지)
    │  - 지각 품질 평가
    │  - 의미론적 아티팩트 감지
    │  - VLM 기반 필터
    │  - 콘텐츠 유형 분류
    │
    ▼
5. Video Captioning (5초 윈도우로 캡셔닝)
    │
    ▼
6. Semantic Deduplication (임베딩 클러스터링으로 중복 제거)
    │
    ▼
7. Structured Sharding (콘텐츠 유형/해상도/길이별 정리)
```

### 8.2 Post-Training용 데이터 준비 베스트 프랙티스

Post-training에서는 위 파이프라인을 **축소하여** 적용합니다:

**필수 단계:**

1. **비디오 품질 확인**
   - 해상도: 720p 이상
   - 프레임 수: 93프레임 이상 (약 4초 @ 24fps)
   - 흔들림, 블러가 심하지 않은 영상

2. **캡션 작성**
   - 장면의 주요 객체, 동작, 환경을 구체적으로
   - 영어로 작성 (모델의 사전 학습 언어)
   - 지나치게 짧거나 긴 캡션 피하기

3. **도메인 일치**
   - 목표 도메인과 관련된 비디오만 포함
   - 관련 없는 비디오는 노이즈로 작용

**권장 단계:**

4. **데이터 다양성 확보**
   - 다양한 각도, 조명, 시간대
   - 다양한 객체 배치, 움직임 패턴
   - 극단적인 사례(어두운 장면, 빠른 움직임 등)도 소량 포함

5. **품질 기반 필터링**
   - 저품질 비디오 제거
   - 워터마크/자막 있는 영상 제거
   - 비디오-캡션 불일치 확인

6. **규모 점진적 확대**
   - 소규모(50-100)로 시작하여 파이프라인 검증
   - 결과 확인 후 데이터 규모 확대
   - 각 라운드의 평가 결과로 다음 큐레이션 방향 결정

### 8.3 데이터 양 vs 품질의 균형

```
                 성능
                  │
                  │         ╭───────── 고품질 데이터
                  │       ╱
                  │     ╱
                  │   ╱
                  │ ╱
                  │╱   ╭─────────── 저품질 데이터
```

### 9.1 torchrun과 분산 학습

### 9.2 데이터 병렬화의 흐름

```
학습 데이터셋
    │
    ▼ (DataLoader + DistributedSampler)
┌───┬───┬───┬───┬───┬───┬───┬───┐
│GPU│GPU│GPU│GPU│GPU│GPU│GPU│GPU│
│ 0 │ 1 │ 2 │ 3 │ 4 │ 5 │ 6 │ 7 │
└─┬─┴─┬─┴─┬─┴─┬─┴─┬─┴─┬─┴─┬─┴─┬─┘
  │   │   │   │   │   │   │   │
  ▼   ▼   ▼   ▼   ▼   ▼   ▼   ▼
 Forward Pass (각 GPU에서 독립 실행)
  │   │   │   │   │   │   │   │
  ▼   ▼   ▼   ▼   ▼   ▼   ▼   ▼
 Backward Pass + Gradient 계산
  │   │   │   │   │   │   │   │
  └───┴───┴───┴───┴───┴───┴───┘
              │
              ▼ (All-Reduce: 그래디언트 평균)
              │
              ▼
        파라미터 업데이트 (모든 GPU 동기화)
```

### 9.3 체크포인트의 분산 저장 (DCP)

```
DCP 체크포인트 구조:
iter_000001000/
├── model/
│   ├── .metadata          # 텐서 매핑 정보
│   └── __0_0.distcp       # 분산된 가중치 데이터

DCP의 장점:
- 각 GPU가 자신의 가중치 조각만 저장/로드
- 병렬 I/O로 빠른 저장/복원
- FSDP와 자연스럽게 호환
```

## 10. 평가와 품질 측정

### 10.1 주요 평가 지표

| 지표 | 측정 대상 | 설명 |
|------|----------|------|
| **FVD** (Frechet Video Distance) | 비디오 품질 | 생성-실제 비디오 분포 거리. 낮을수록 좋음 |
| **FID** (Frechet Inception Distance) | 프레임 품질 | 개별 프레임의 시각적 품질. 낮을수록 좋음 |
| **TSE** (Temporal Structure Error) | 시간 일관성 | 프레임 간 기하학적 일관성 |
| **CSE** (Camera Structure Error) | 카메라 일관성 | 멀티뷰에서의 카메라 구조 오차 |

### 10.2 학습 중 품질 모니터링

학습 중 직접 확인할 수 있는 지표들:

```
1. Loss 추이
   - 초기: ~0.5
   - 중간: ~0.2-0.3
   - 수렴: ~0.1-0.2
   - NaN/Inf → 학습 불안정 (LR 감소 필요)

2. 샘플 품질 (50 iteration마다 자동 생성)
   - 초기: 노이즈가 많고 흐릿함
   - 중간: 구조가 잡히기 시작
   - 후기: 선명하고 일관된 영상

3. W&B 곡선 (활성화한 경우)
   - Loss: 부드럽게 감소
   - LR: warmup 후 안정적
   - 그래디언트 norm: 폭발 없이 안정적
```

### 10.3 Overfitting 감지와 방지

```
Overfitting (과적합) 징후:
- 학습 Loss는 감소하지만 샘플 품질이 저하
- 학습 데이터와 매우 유사한 영상만 생성 (다양성 부족)
- 새로운 프롬프트에 대한 반응이 약함

방지 방법:
1. 학습 데이터 양 증가 (다양성 확보)
2. 학습 반복 횟수 조절 (너무 오래 학습하지 않기)
3. 적절한 학습률 설정
4. EMA 체크포인트 사용 (일반화 성능 향상)
```

## 핵심 용어 정리

| 용어 | 설명 |
|------|------|
| **DiT** | Diffusion Transformer. Transformer 기반 diffusion 모델 아키텍처 |
| **ControlNet** | 사전 학습된 모델에 공간적 제어를 추가하는 아키텍처 |
| **Latent Space** | 고차원 데이터를 저차원으로 압축한 표현 공간 |
| **state_t** | 시간 축 잠재 공간 크기 (24 = 93 프레임의 압축 표현) |
| **context_parallel_size** | 시퀀스를 GPU에 분배하는 병렬화 파라미터 |
| **FSDP** | Fully Sharded Data Parallel. 모델을 GPU에 분산 저장하는 기법 |
| **DCP** | Distributed Checkpoint. 분산 학습용 체크포인트 형식 |
| **EMA** | Exponential Moving Average. 가중치의 이동 평균 |
| **AdaLN** | Adaptive Layer Normalization. 시간 조건부 정규화 |
| **WFM** | World Foundation Model. 물리 세계 시뮬레이션을 위한 기반 모델 |
| **Guidance Scale** | 추론 시 텍스트 조건의 영향력을 조절하는 파라미터 |
| **Warmup** | 학습 초기에 학습률을 점진적으로 올리는 기법 |
